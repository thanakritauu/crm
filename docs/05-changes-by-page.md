# สรุปสิ่งที่เปลี่ยนจากเว็บเดิม แยกตามหน้า (สำหรับ dev)

ต้นฉบับ: https://club.charmiss.co/charmiss/… · ตรวจเมื่อ 17 พ.ย. 2569
Prototype: `src/routes/[id]/…` (`[id]` = partner เหมือนต้นฉบับ)

**ที่มาของแต่ละหน้า**
- ✅ **เทียบหน้าจริงแล้ว** — เปิดดูหน้าจริง (หลังล็อกอิน หรือหน้าที่เปิดได้โดยไม่ล็อกอิน) แล้วปรับให้ตรง
- 📦 **จาก bundle** — สร้างจาก HTML template / โค้ดใน JS bundle ของต้นฉบับ (หน้าจริงต้องมีข้อมูลเฉพาะที่บัญชีที่ใช้ตรวจไม่มี) โครงและ class ตรงกับโค้ด แต่ยังไม่ได้เห็นหน้าจริงที่มีข้อมูล

ชื่อไฟล์ chunk ในวงเล็บ = ไฟล์ใน `/_build/assets/` ของต้นฉบับที่ใช้อ้างอิง

## 6. ข้อสังเกตสำหรับ dev
- ปุ่มย้อนกลับใน `NavigationTopbar` เป็นลูกศรขาวบน `bg-black/10` เสมอตามต้นฉบับ บนหน้าพื้นขาวมองเห็นยาก
- ต้นฉบับใช้ `hover:text-blue-500` ในแถบล่าง (คงไว้ตามจริง)
- คีย์ i18n ที่โค้ดต้นฉบับเรียกแต่ไม่มีใน dictionary: `pointCollection.*`, `dialog.registration_completed`
- ชื่อ `privilage`, `teriary`, `tems-conds` สะกดตามต้นฉบับโดยตั้งใจ

## 8. ปรับทั้งแอปให้ตรง Design System (ยึด Figma)

กติกาเต็มอยู่ที่ [02-design-system.md](02-design-system.md) · ตัวอย่างที่ `/styleguide` · ตรวจด้วย `npm run lint:ds`

- **Token:** `tailwind.config.cjs` เปลี่ยนเป็นค่าจาก Figma ทั้งหมด
  - ตัวอักษร: 5 ขนาด (24/18/16/14/12) line-height 1.5
  - สีตามชื่อ Figma และเอาพาเลตต์ Tailwind เริ่มต้นออก
  - เงา `shadow-card`
  - มุมโค้ง 8/12/16/24/แคปซูล
- **แปลงทั้งโค้ด (94 ไฟล์):**
  - `text-[13px]` และค่าทำนองเดียวกันปัดเข้า 5 ขนาด; น้ำหนักบังคับเป็นคู่ตามสไตล์ Figma เท่านั้น
  - สี hex กว่า 80 ค่ารวมเหลือ token ชุดเดียว
  - ระยะห่างปัดลงฐาน 8 (ยอม 4 สำหรับช่องแคบภายใน)
- **Component กลาง:**
  - ใหม่: `PageHeader`, `PillTabs`, `InfoTabs`, `ui/modal` (ResultModal / ConfirmModal / AlertDialog / InfoBox), `Card`
  - ปรับใหม่: `Button` (สูง 48/40/32), `Input` (สูง 48), `Sheet`, `Dialog`, `Badge`, `EmptyData`, `NavigationTopbar`
- **รวมของซ้ำ:**
  - แท็บ 5 แบบ (segmented / header-pill / figma pill / ui tabs / info-tabs ×2) เหลือ `PillTabs` + `InfoTabs`
  - bottom sheet 2 แบบเหลือ `Sheet`; modal 3 แบบใช้เปลือกเดียวกัน
  - ลบ component ที่ไม่ได้ใช้ 9 ไฟล์
- **ทุกหน้า:**
  - หัวหน้าเพจที่เขียนเองเปลี่ยนเป็น `PageHeader` (ยกเว้นหน้าที่วางบนรูปปกยังใช้ `NavigationTopbar`)
  - ปุ่มที่เขียนเองเปลี่ยนเป็น `Button`
  - ช่องกรอกเปลี่ยนเป็น `Input`; สถานะว่างเปลี่ยนเป็น `EmptyData`
  - แถวรายการใช้ `py-4 border-b border-stroke` เหมือนกันทั้งแอป
- **ธีมหลาย partner:** เพิ่มตัวแปร `--primary-surface`, `--primary-300/400`, `--secondary-surface` ที่คำนวณจากสีหลักของ partner (`color-mix`)
- `cn()` ตั้งค่า tailwind-merge ให้รู้จัก token ใหม่ (`text-12` ไม่ถูกตัดทิ้งเมื่อรวมกับ `text-primary`)

## 9. กฎน้ำหนักตัวอักษร: ห้าม Bold

- ทั้งแอปใช้ 2 น้ำหนัก: **Medium = พื้นฐาน** (ตั้งที่ `body`) และ **Semibold = หัวข้อ/ตัวเน้น**
- `font-bold` → `font-semibold` และ `font-normal` → `font-medium` ทั้งโค้ด; `<b>` `<strong>` และ CSS ใน policy เป็น 600
- เอา `bold` / `normal` ออกจาก Tailwind config และ `npm run lint:ds` แจ้งเตือนเมื่อพบ

## 10. ปรับกฎน้ำหนักตัวอักษร (3 ระดับ)

- **Semibold** = หัวข้อ · **Medium** = แท็บ, badge, ป้ายกำกับฟอร์ม (รวมชื่อเมนู ชื่อปุ่มแบบแผ่น) · **Regular** = ข้อความทั่วไป วันที่ เงื่อนไข กล่องข้อมูล (พื้นฐานที่ `body`) · ยังห้าม Bold
- `PillTabs`, `Badge`, `Label` เปลี่ยนเป็น Medium; คำอธิบาย วันที่ เงื่อนไข ค่าในช่องกรอก และแถวสรุปคะแนนกลับเป็น Regular
- เพิ่ม `font-normal` กลับใน Tailwind และ lint

## 11. ฟังก์ชันหน้าสะสมคะแนน (`/:partner/point-collection`)

- **แสกนคิวอาร์โค้ด** (Figma "ScanQR"): เปลี่ยนจากจอดำ + ปุ่มจำลอง เป็น `components/point/qr-scanner-screen.tsx`
  - เปิดกล้องหลังจริงและอ่าน QR อัตโนมัติด้วย `qr-scanner` (ไลบรารีเดียวกับเว็บเดิม)
  - กรอบสแกน 260 มุม 24 + พื้นดำ 30% รอบกรอบ (`shadow-scan-mask`)
  - แถบล่างมีปุ่มคลังรูป (อ่าน QR จากรูป) และปุ่มไฟฉาย (ใช้ได้เฉพาะเครื่องที่รองรับ เช่น Android)
  - เปิดกล้องไม่ได้ (คอมไม่มีกล้อง / ไม่อนุญาต / ไม่ใช่ https) → มีปุ่มจำลองผลแทน

  - สแกนรหัสเดิมซ้ำ → "คิวอาร์โค้ดนี้ถูกใช้งานแล้ว"
  - รหัสอื่น หรือรูปที่ไม่มี QR → "ไม่พบคิวอาร์โค้ดนี้ในระบบ"
  - โหมดภารกิจ (`?mission=`) ใช้กติกาเดียวกัน แต่ได้แสตมป์/ความคืบหน้าแทนคะแนน
- **QR ตัวอย่างสำหรับทดสอบ:** หน้า `/qr` (ลิงก์อยู่ในเมนู prototype และหน้า /prototype)
- **แก้บั๊ก:** เลือกรูปจากหน้าสแกนเคยถูกส่งไปเป็น "ส่งตรวจสอบใบเสร็จ 48 ชม." ตอนนี้เป็นการอ่าน QR จากรูปแล้ว
- **กดเพื่ออัปเดตคะแนนจากแพลตฟอร์มออนไลน์:**
  - ยังไม่เชื่อมต่อแพลตฟอร์มใด → modal ชวนไปหน้าเชื่อมต่อ
  - เชื่อมต่อแล้ว → ดึงคำสั่งซื้อจำลองแพลตฟอร์มละ 1 รายการ (+50 คะแนน) และลงประวัติ
  - กดซ้ำโดยไม่มีคำสั่งซื้อใหม่ → "คะแนนของท่านเป็นปัจจุบันแล้ว"
- "รีเซ็ตข้อมูลจำลอง" ล้างรหัส QR ที่ใช้แล้วและสถานะการซิงก์ด้วย
- ถ่ายรูปใบเสร็จ / กรอกเลขที่ใบเสร็จ / กรอกรหัสสินค้า ยังทำงานเหมือนเดิม

## 12. ฟังก์ชันหน้าโปรไฟล์ + ระบบสองภาษา

**ข้อมูลส่วนตัว (Figma Profile → Prosonal Info → OTP → toast):**
- เปลี่ยนเบอร์มือถือ → ไปยืนยัน OTP ที่เบอร์ใหม่ (`verify-by-phone?action=change_phone&phone=…&path=profile`)
  - ยืนยันแล้วจึงบันทึกข้อมูลทั้งฟอร์ม (เก็บรอไว้ใน `lib/pending-profile.ts`)
  - กดย้อนกลับจากหน้า OTP = กลับไปแก้ฟอร์ม
- แก้ช่องอื่นโดยไม่เปลี่ยนเบอร์ → บันทึกทันที
- บันทึกสำเร็จ → กลับหน้าโปรไฟล์พร้อม toast "อัปเดตข้อมูล สำเร็จ" (ตัด modal คั่นออกตาม Figma)
  - toast เป็นพื้นเขียวอ่อนตาม Figma Style4
- วันเกิดล็อกหลังบันทึกครั้งแรก + ข้อความ "วันเกิดถูกบันทึกแล้วและไม่สามารถเปลี่ยนแปลงได้" ใต้ช่อง

**ระบบสองภาษา (ไทย / English) ทั้งแอป:**
- เลือกภาษาจากเมนู "ภาษา" ในหน้าโปรไฟล์ (เก็บใน `session.language`) แล้วทุกหน้าเปลี่ยนทันที
- `src/lib/i18n.tsx` โหลดทุกไฟล์ใน `src/i18n` อัตโนมัติ
  - `th.json` / `en.json` = dictionary หลัก (789 key จากเว็บเดิม + คำแปลอังกฤษ)
  - `pages/<ส่วน>.th.json` / `.en.json` = ข้อความที่ prototype เพิ่ม (`core.` `loyalty.` `account.` `me.`)
  - รวม 962 key ทั้งสองภาษาครบเท่ากัน
- ใช้ `t("key", { param })` ใน component หรือ `translate()` นอก component
  - วันที่ใช้ `formatDate()` / `intlLocale()`: ไทยแสดงปี พ.ศ., อังกฤษแสดง "14 March 1998"
- ปฏิทินวันเกิดแสดงชื่อเดือน/วันตามภาษา
- บนการ์ดสมาชิก ภาษาอังกฤษย่อคำว่า "points" เป็น 14px เพื่อไม่ชนปุ่ม
- **ยังเป็นภาษาไทย (ถือเป็นข้อมูลจาก backend):**
  - ข้อมูลจำลองใน `src/mocks` เช่น ชื่อสินค้า ภารกิจ สิทธิพิเศษ แท็ก นโยบาย และชื่อผู้ใช้

  - คูปองที่ระบบสร้างจากการแลกคะแนน

## 14. ฟังก์ชันคูปองของฉัน

- **ใช้คูปอง:** กดยืนยัน → คูปองเป็น "ใช้งานแล้ว" ทันที (ย้ายไปแท็บใช้งานแล้ว/หมดอายุ) แล้วเปิด modal รหัส
  - ภายใน 10 นาทีหลังยืนยัน กลับมาหน้ารายละเอียดจะมีปุ่ม "แสดงรหัส" เปิดรหัสเดิมได้ เวลานับต่อจากเดิม
  - หมดเวลา → ปุ่มเทา "คูปองถูกใช้งานแล้ว" · ใน modal แสดง "รหัสหมดอายุแล้ว"
  - เดิม: คูปองเปลี่ยนสถานะเฉพาะตอนกด "กลับหน้าคูปองของฉัน" ถ้าปิด modal ด้วยวิธีอื่นคูปองยังใช้ได้
- **หน้ารายละเอียด** (Figma Coupon_Detail 4 แบบ):
  - ใช้แล้ว/หมดอายุ = รูปทับดำโปร่ง + "คูปองถูกใช้งานแล้ว" / "คูปองหมดอายุ" และปุ่มเทากดไม่ได้
  - รูปโหลดไม่ได้ = พื้นเทาอ่อน + ไอคอน APIError
- **หมดอายุอัตโนมัติ:** คูปองพร้อมใช้ที่เลยสิ้นวัน `expires_at` เปลี่ยนเป็นหมดอายุเมื่อเปิดแอป
- **หน้าแรก ส่วน "คูปองของฉัน"** (Figma Logic box):
  - ยังไม่เคยมีคูปอง → ไม่แสดงส่วนนี้
  - มีคูปองพร้อมใช้ → แสดงการ์ด 2 ใบ
  - เคยมีแต่ใช้/หมดอายุหมดแล้ว → สถานะว่าง "ยังไม่มีคูปองในขณะนี้"
- **เมนู prototype:** เพิ่มปุ่มสลับข้อมูลคูปอง "มีคูปองพร้อมใช้ / ใช้หมดแล้ว / ยังไม่เคยมี" เพื่อดูทั้ง 3 สถานะ

## 15. ฟังก์ชันประวัติคะแนน

สถานะใน Figma ทั้ง 6 แบบมีอยู่แล้ว (ไม่มีวันหมดอายุ / มีวันหมดอายุ 3 แท็บ / ว่าง / ใช้แลก / หมดอายุ / ขยายดูรายละเอียดสินค้า) รอบนี้แก้ 2 จุด:

- **แท็บ "หมดอายุ" คำนวณจากคะแนนจริง** (`expiringPoints()` ใน `services/history-service.ts`) แทนแถวตัวอย่างคงที่
  - คะแนนที่ได้รับแต่ละครั้งหมดอายุ 12 เดือนหลังวันที่ได้รับ
  - คะแนนที่ใช้ไปหักจากก้อนเก่าสุดก่อน (เข้าก่อนออกก่อน) จึงคิดจากยอดคงเหลือปัจจุบัน — ผลรวมในแท็บเท่ากับ "คะแนนทั้งหมด" เสมอ
  - แสดง "คุณมี X คะแนน ที่จะหมดอายุภายในวันที่ …" เรียงจากใกล้หมดอายุที่สุด ก้อนที่เลยวันแล้วแสดง "หมดอายุแล้วเมื่อวันที่ …"
  - เปิดแท็บนี้ได้จากเมนู prototype → "คะแนนมีวันหมดอายุ"
- **ปุ่มย้อนกลับ** กลับหน้าที่มา (แลกของรางวัล / แลกคะแนน / หน้าแรก ฯลฯ) แทนการไปหน้าแรกเสมอ

## 17. ฟังก์ชันสิทธิพิเศษ (Figma Reward)

- **จัดส่งถึงบ้าน** → หน้าสรุปคำสั่ง `privilage/summary/:id` (Figma Summary_Address / Summary_NonAddress)
  - มีที่อยู่: การ์ดที่อยู่ (ค่าเริ่มต้น / ที่เลือก) + "เลือก" → สมุดที่อยู่โหมดเลือก
  - ไม่มีที่อยู่: กล่องแจ้ง + "เพิ่มที่อยู่" · ปุ่มยืนยันกดไม่ได้ · เพิ่มเสร็จกลับมาพร้อมที่อยู่ใหม่ทันที
  - ยืนยัน → "แลกสินค้าสำเร็จ! รอรับสินค้าได้เลย" → กลับหน้าประวัติการแลก
- **รับที่หน้าร้าน** → ยืนยัน (รหัสหมดอายุ 10 นาทีตาม Figma) → รหัส QR/บาร์โค้ด/โค้ด · บันทึกวิธีรับและรหัสในประวัติ
- **สมุดที่อยู่** (`personal-information/address`, `/new`, `/edit/:id`, `services/address-service.ts`)
  - เก็บได้หลายที่อยู่ · ประเภท บ้าน/ที่ทำงาน/อื่นๆ · ตั้งค่าเริ่มต้น · แก้ไข / ลบ (ยืนยันก่อนลบ) · toast เพิ่ม/แก้ไข/ลบสำเร็จ
  - โหมดเลือก: `?select=1&return=<path>&selected=<id>` → กดการ์ดแล้วกลับ `<path>?address=<id>`
- **ประวัติการแลก** (แท็บในหน้าสิทธิพิเศษ, Figma History): การ์ดรูปทับเทา "แลกแล้ว" + ป้ายสถานะ + ชื่อ · กดดูรายละเอียด
  - สถานะ: แลกที่ร้าน · ได้รับคูปองแล้ว · จัดส่งเดินเองตามเวลาหลังแลก — 0–1 นาที กำลังจัดเตรียมสินค้า · 1–3 นาที อยู่ระหว่างการนำส่ง · 3 นาทีขึ้นไป ได้รับสินค้าเรียบร้อยแล้ว
- **รายละเอียดที่แลกแล้ว** (`privilage/detail/:id?redeem=<id>`, Figma Reward_Detail_usedAt Shop / Reward_Detail_Delivery): รูปทับเทา "แลกแล้ว" + สถานะ + ที่อยู่จัดส่ง (ถ้าจัดส่ง) · ไม่มีกล่องคะแนนและปุ่มแลก
- "รีเซ็ตข้อมูลจำลอง" ล้างสมุดที่อยู่ด้วย

## 18. ฟังก์ชันภารกิจ (Figma Mission)

- **ภารกิจสะสมคอยน์** (ประเภทใหม่ `type: "coin"`, ตัวอย่าง `cm-201` กำลังทำ / `cm-202` หมดเขตแลก)
  - คอยน์แยกตามภารกิจ: แถบ "จำนวนคอยน์ที่สะสมได้" · กติกาได้คอยน์เป็นบูลเล็ต · ระยะเวลาภารกิจ + ระยะเวลาการแลก
  - "รางวัลที่แลกได้" ราคาเป็นคอยน์ ("ใช้ 5 คอยน์") → ยืนยัน → แลกสำเร็จ · คอยน์ไม่พอ = "คอยน์ยังไม่พอ" บอกจำนวนที่ขาด
  - รางวัลที่แลกแล้ว / หมดเขตแลก มีป้ายทับรูป · ภารกิจหมดเวลาปุ่ม "สะสมคะแนน" เป็นสีเทา
  - ปุ่ม: ยังไม่เริ่ม "เริ่มภารกิจ" (ยืนยัน "เริ่มภารกิจเลยไหม?") → "สะสมคะแนน" ไปหน้าสะสมคะแนนโหมดภารกิจ
  - สะสมคะแนนในโหมดภารกิจ (สแกน QR / ถ่ายใบเสร็จ / กรอกเลขที่ใบเสร็จ / รหัสสินค้า) ได้ 10 คอยน์เข้าภารกิจนั้น
  - ได้/ใช้คอยน์ลงประวัติคอยน์รวม ("คุณได้รับ 10 คอยน์ จากการทำภารกิจ …" / "คุณใช้ 5 คอยน์ แลก …")
  - การ์ดในหน้ารายการแสดงคอยน์คงเหลือแทนแถบความคืบหน้า
- **ภารกิจแสตมป์**
  - กดรางวัลก่อนทำสำเร็จ → "ยังไม่สามารถแลกสินค้าได้ในตอนนี้ / ทำภารกิจให้สำเร็จ แล้วแลกของรางวัลกันเลย"
  - ทำครบแล้วเปิดหน้ารายละเอียดครั้งแรก → "ยินดีด้วย / คุณทำภารกิจ … สำเร็จแล้ว แลกของรางวัลได้เลย" (แสดงครั้งเดียว)
- **หน้ารายการ**: ไม่มีภารกิจเลย = "ยังไม่มีภารกิจในขณะนี้" · กรองแล้วไม่พบ = "ไม่พบภารกิจที่คุณหา"
- แก้บั๊ก: ยืนยันแลกด้วยคอยน์เคยพังเพราะ modal ปิดตัวเองก่อนอ่านรางวัลที่เลือก

## 22. แก้ UX กลุ่ม C

- **ย้อนกลับ:**
  - `useGoBack` ไปปลายทางแบบ replace (ไม่สะสมประวัติ ปุ่ม back ของเครื่อง/LINE ไม่วน) · กลับหน้ารายการแพลตฟอร์มก็ replace
  - `NavigationTopbar onBack` · หน้า OTP ขั้นที่ 2 ย้อนกลับ = กลับไปแก้เบอร์ (เปลี่ยนเบอร์ = หน้าข้อมูลส่วนตัว, สมัครสมาชิก = หน้าสมัคร)
  - ตอบคำถามแพลตฟอร์ม: ย้อนจากคำถามแรกยังเก็บหมายเลขคำสั่งซื้อ
  - ฟอร์มที่แก้แล้วยังไม่บันทึก (ข้อมูลส่วนตัว / เพิ่ม-แก้ไขที่อยู่) กดย้อนกลับ → `DiscardChangesModal` "ทิ้งการแก้ไขหรือไม่?" (ทิ้ง = แดง / แก้ไขต่อ)
- **ตรวจฟอร์มแบบเดียวกันทุกหน้า:** ปุ่มกดได้เสมอ · ข้อความผิดใต้ช่องเมื่อออกจากช่อง และทุกช่องเมื่อกดบันทึก/ถัดไป — สมัครสมาชิก, ฟอร์มที่อยู่ (รวมจังหวัด/อำเภอ/ตำบล และประเภท), กรอกเบอร์หน้า OTP · ช่องเบอร์เป็น `type="tel"` + autocomplete
- **สมัครสมาชิกผ่าน OTP:** กดถัดไป → เก็บข้อมูล (`lib/pending-register.ts`) → `verify-by-phone?action=register&phone=…` (ข้ามขั้นกรอกเบอร์) → OTP ผ่าน = บันทึก + เป็นสมาชิก → `register?done=1` หน้าสำเร็จ · ย้อนกลับ/ผิดครบ = กลับหน้าสมัครโดยข้อมูลยังอยู่ · เบอร์ 0811111111 แจ้งในหน้าสมัคร "เบอร์นี้ถูกใช้สมัครแล้ว"
- **Guest:**
  - ปุ่มเปลี่ยนภาษา (ธง + TH/EN) มุมขวาบนหน้า landing
  - หน้าโปรไฟล์ของ Guest มีแถวภาษา และชื่อขึ้น "ผู้ใช้งานทั่วไป"
  - `useMemberOnly()` (lib/member-gate) — หน้าข้อมูลส่วนตัว / สมุดที่อยู่ / เพิ่ม-แก้ไขที่อยู่ / ตอบคำถามแพลตฟอร์ม / แลกคะแนนเป็นคูปอง: Guest เปิดด้วย URL → กลับหน้าโปรไฟล์ + modal ชวนสมัคร
- **ประวัติคะแนน/คอยน์แปลตามภาษา:** รายการใหม่เก็บ `key + params + source_key` (`HistoryMsg` ใน session) แล้วแสดงผ่าน `txText()` · ข้อความอยู่ใน `src/i18n/pages/hist.*.json` · ข้อมูลตัวอย่างเดิมยังเป็นข้อความตรง
- **คำตายตัว:** "Valid until" → `loyalty.valid_until` (สีเทาเข้มขึ้น), "MAX" → `loyalty.max`, "Hint:" → `loyalty.hint`
- **ข้อความที่ไม่ตรง:** สิทธิพิเศษที่ยังไม่เริ่ม = "เริ่มแลก <วันที่>" (ทั้งใต้ช่วงเวลาและปุ่ม) แทน "หมดเวลาแลก" · ยืนยันแลกคูปอง (หน้าคูปอง / สิทธิพิเศษประเภทคูปอง) ไม่พูดถึงรหัสหมดอายุ 10 นาทีแล้ว
- **หน้าไม่พบ/ว่าง:**
  - รายละเอียดคูปอง และสรุปสิทธิพิเศษที่ไม่พบ มี header + ปุ่มย้อนกลับ + EmptyData
  - 404 → ปุ่ม "กลับหน้าแรก" ของแบรนด์ (ลิงก์สารบัญ prototype เป็นลิงก์รอง)
  - EmptyData มีข้อความเฉพาะ: ของรางวัลในหมวด, ไม่พบของรางวัล, ยังไม่มีประวัติการแลก
- **หน้าที่ไม่มีลิงก์เข้า:** เพิ่ม "นโยบายคุ้มครองข้อมูลส่วนบุคคล" ในเมนูการตั้งค่าของโปรไฟล์ (→ /policy) · /settings และ /consent ยังไม่มีลิงก์ (settings ซ้ำกับเมนูภาษา, consent เป็นขั้นในขั้นตอน LINE เดิม)

## 25. ระยะห่างทุกหน้า (วัดด้วยสคริปต์ 37 หน้า)

มาตรฐาน
- ขอบซ้าย/ขวาของเนื้อหา 16px (ข้อความในการ์ด 32px)
- เนื้อหาแรกห่างจาก header 16px — header สีชมพู: เว้น 16px ใต้ขอบ · header สีขาว: ต่อทันที (header มี padding ล่าง 16px อยู่แล้ว = ห่างจากชื่อหน้า 16px)
- หน้ารายละเอียดที่เริ่มด้วยรูปปก: เนื้อหาห่างจากรูป 16px (ยกเว้นแถบสถานะภารกิจที่ติดรูปตาม Figma)

ผลการวัด: ขอบซ้าย/ขวา ผ่านทั้ง 37 หน้า · ระยะใต้ header ที่ไม่ตรงและแก้แล้ว:
- สรุปแลกของรางวัล 24 → 16 (เอา pt-2 ของส่วนที่อยู่ออก)
- ภารกิจตอบคำถาม 32 → 16 (เอา mt-4 ของกล่องคำถามออก)
- อันดับคอยน์ 24 → 16 (py-6 → pt-4 pb-6)
- แลกคะแนนเป็นคูปอง 24 → 16 (pt-6 → pt-4)
- (ก่อนหน้า) รายการสิทธิพิเศษ ชิปแท็ก 0 → 16 · รายละเอียดสิทธิพิเศษ ขอบแท็บข้อมูล 0 → 16 และแท็บ→รายการ 41 → 16
ข้อยกเว้นตาม Figma: ข้อมูลส่วนตัว (รูปโปรไฟล์ซ้อนขอบ header)

## 32. หน้าแรก / แลกรางวัล / ภารกิจ แบบ Okya — แยก "คะแนน" กับ "คอยน์" ชัดเจน

หลักที่ใช้: **คะแนน** = ได้จากการซื้อทุกช่องทาง ใช้แลกในหน้าแลกรางวัล (ไอคอน P สีชมพู) · **คอยน์** = ได้จากภารกิจ ใช้แลกรางวัลของภารกิจ (เหรียญ C สีส้ม) · ระดับสมาชิกคิดจาก**คะแนน**อย่างเดียว · คอยน์ของภารกิจสะสมคอยน์เป็นของภารกิจนั้น (ไม่รวมกับยอดคอยน์)

- การ์ดสองฝั่ง **คะแนน | คอยน์** แทนการ์ดสมาชิกสีชมพู: แต่ละฝั่งมียอด + วิธีได้ ("ซื้อสินค้าเพื่อสะสม" / "ทำภารกิจเพื่อสะสม") + ลูกศร → ประวัติของสกุลนั้น · เปิด "คะแนนมีวันหมดอายุ" → บรรทัด "X คะแนนจะหมดอายุ …" → แท็บหมดอายุ

## 33. แถบล่าง: ภารกิจแทนแจ้งเตือน · กระดิ่งแทนปุ่ม QR

- **`useGoBack`**: มีหน้าก่อนหน้าในแอป → `history.back()` เสมอ · เปิดหน้าตรงจากลิงก์/LINE/รีเฟรช (ไม่มีหน้าก่อนหน้า) → ไปหน้าแม่ (`backTo`/`navTo`) แบบ replace · รู้ว่ามีหน้าก่อนหน้าจาก `_depth` ของ router เทียบกับหน้าแรกที่เปิดแอป (`markEntryDepth` ใน `app.tsx`)
- **`useBackWith`**: ย้อนกลับพร้อมผลลัพธ์ — บันทึก/ลบที่อยู่ → กลับรายการพร้อม toast · เลือกที่อยู่ตอน checkout → กลับหน้าสรุปพร้อม `?address=` · บันทึกข้อมูลส่วนตัว → กลับโปรไฟล์พร้อม toast — ไม่สร้างหน้าซ้ำในประวัติ (toast ส่งผ่าน `takeFlash()`)
- เลิกใช้ `state.from` ทั้งหมด (กระดิ่ง, การแจ้งเตือน, แลกคะแนนเป็นคูปอง, โปรไฟล์)
- เอา `onBack` ที่พาไปหน้าตายตัวออก: คูปองของฉัน, เชื่อมต่อแพลตฟอร์ม, กรอกเลขใบเสร็จ/รหัสสินค้า, ตัวอย่างใบเสร็จ, สมุดที่อยู่ (โหมดเลือก), เพิ่ม/แก้ไขที่อยู่, ข้อมูลส่วนตัว, แพลตฟอร์มรายตัว — `onBack` ที่เหลือใช้เฉพาะย้อนขั้นตอนภายในหน้า (OTP, ขั้นที่ 2 ของแพลตฟอร์ม) และถามก่อนออกเมื่อแก้ไขยังไม่บันทึก
- `backTo` ทุกหน้า = หน้าแม่ ใช้เฉพาะตอนเปิดหน้าตรง (เพิ่มให้หน้าอันดับคอยน์)

## 52. เมนูล่างระยะเท่ากัน · ">" กลับมาที่การ์ดหน้าแรก · คะแนน/คอยน์ปลิวเข้าเมนูหน้าแรก

- **การ์ดหน้าแรก**: "คะแนนของคุณ >" / "คอยน์ของคุณ >" กลับมาเหมือนเดิม (กด > → ประวัติของสกุลนั้น)
- **แอนิเมชันสะสมสำเร็จ**: ทุกครั้งที่ได้คะแนน/คอยน์ (`sessionActions.addPoints` / `addCoins`) ไอคอน P หรือ C 7 ดวงกระจายจากกลางจอ แล้วปลิวลงไปที่ปุ่ม **"หน้าแรก"** ในเมนูล่าง → ปุ่มเด้งเบาๆ · เปิดหน้าแรกจะเห็นตัวเลขนับขึ้น (count-up) ตามเดิม
  - ลอยเหนือ modal/ป๊อปอัปผลลัพธ์ · ถ้าตอนได้คะแนนอยู่หน้าที่ไม่มีเมนูล่าง → เก็บไว้ แล้วปลิวตอนเมนูล่างโผล่
  - ผู้ใช้ที่ตั้ง "ลดการเคลื่อนไหว" ในเครื่อง → ไม่เล่น
  - โค้ด: `src/components/layout/fly-to-home.tsx` (อีเวนต์ `charmiss:earned`) · ปุ่มเมนูมี `data-nav="home"`
- **ระบบกลางแอนิเมชันได้รับ** (ใช้เหมือนกันทุกช่องทาง): **ได้คะแนน → เหรียญ P ปลิว · ได้คอยน์ → เหรียญ C ปลิว** ไปที่ปุ่มหน้าแรก
  - จุดเดียว: `sessionActions.addPoints` / `addCoins` — ทุกช่องทางที่ให้คะแนน/คอยน์ผ่าน 2 ฟังก์ชันนี้ (สแกน QR · กรอกใบเสร็จ/รหัสสินค้า · ซิงก์แพลตฟอร์ม/ปุ่มอัปเดตหน้าแรก · ภารกิจสำเร็จ: แสตมป์/เช็กอิน/ควิซ) ช่องทางใหม่ต้องเรียก 2 ฟังก์ชันนี้ แอนิเมชันจะมาเอง · ยอดติดลบ (ใช้/แลก) ไม่เล่น
  - ได้หลายครั้งติดกัน (เช่น ซิงก์หลายแพลตฟอร์ม) → ปลิวครั้งเดียวต่อสกุล
  - ตรวจแล้ว: กรอกใบเสร็จ → +150 คะแนน → ปิดป๊อปอัป กลับหน้าสะสมคะแนน → P 7 ดวงปลิว (ครั้งเดียว) · ภารกิจแสตมป์ m-001 ครบ → +50 คอยน์ → C 7 ดวงปลิว

## 53. ป้ายแจ้งเตือนวงกลม · คอยน์ภารกิจปลิวเข้ายอดภารกิจ · เปลี่ยนชื่อเมนู/ข้อความ

- **ป้ายตัวเลขแจ้งเตือน** (กระดิ่งหน้าแรก + แถวแจ้งเตือนในโปรไฟล์): วงกลมแดงกว้าง = สูง 20px เสมอ (เดิมสูง 16 แต่กว้างตามตัวเลข+padding เลยเป็นวงรี) · 1 หลัก และ "9+" ก็ยังเป็นวงกลม
- **คอยน์ที่สะสมเข้าภารกิจประเภทสะสมคอยน์** (ไม่เข้ายอดคอยน์หลัก): เหรียญ C ปลิวไปที่ยอด **"คอยน์ของภารกิจนี้"** ในหน้ารายละเอียดภารกิจ แล้วตัวเลข **นับขึ้น** (เหมือนหน้าแรก) — สะสมจากหน้ากรอกใบเสร็จ/สแกน → กลับหน้าภารกิจ → เหรียญปลิว → ยอดนับจากเดิมไปใหม่
  - ระบบกลางเดียวกัน (`fly-to-home.tsx`) เพิ่มปลายทาง: `home` (ปุ่มหน้าแรก) · `mission-coins:<id>` (ยอดคอยน์ภารกิจ) · ส่งจาก `missionService.addMissionCoins`
  - ตัวเลขที่รอเหรียญ (หน้าแรก + ยอดภารกิจ) ค้างยอดเดิมไว้ แล้วเริ่มนับตอนเหรียญดวงแรกถึง (ไม่นับเสร็จก่อนเหรียญมา)
  - ตรวจแล้ว: ภารกิจ cm-201 กรอกใบเสร็จ → กลับหน้าภารกิจ → C 7 ดวงปลิว · ยอดค้าง 10 จนเหรียญถึง แล้วนับเป็น 20
- โปรไฟล์: เมนู "การแลกรางวัลของฉัน" → **"ประวัติการแลกของรางวัล"** (ชื่อหน้า `/wallet/redemptions` เปลี่ยนตาม · EN "Reward redemption history")
- เชื่อมต่อแพลตฟอร์ม › แถบโปรโมชัน LINE: "พิเศษ! รับคะแนน x10 …" → **"พิเศษ! รับคะแนน 10เท่า เมื่อสั่งซื้อผ่าน LINE Shopping"**
- **หน้าแรก › สไลด์แบนเนอร์**: ใช้รูปจริงจากเจ้าของ 4 รูป (2400×1200 = 2:1 พอดีช่อง ไม่ถูกตัด) ย่อเป็น 1200×600 jpg → `public/images/home/slide-1..4.jpg` · เอาสไลด์ตัวอย่าง 4:1 และช่องเทาบอกขนาดออก
- **หน้าแรก › ระดับสมาชิก**: การ์ดขาวแบบเดิม (ตรา 40 · ชื่อระดับ · แถบความคืบหน้าชมพู · ">") **สอดอยู่ใต้การ์ดชมพู** — ชมพูทับขอบบนการ์ดขาว 16px ให้ดูติดเป็นชุดเดียวกัน · การ์ดขาวไม่มีมุมโค้งด้านบน (โค้งเฉพาะล่าง) (ลองแบบแถวในการ์ดชมพูตัวขาวแล้ว → เจ้าของเลือกแบบการ์ดขาวทับ) · ยังเปิด/ปิดได้จากเมนู prototype
- **หน้าแรก › popup ต้อนรับ** (Charmiss CLUB): เดิมขึ้นเฉพาะหลังสมัครสมาชิก → **ขึ้นเองเมื่อเปิดหน้าแรก ครั้งเดียวต่อการเปิดแอป** จนกว่าจะติ๊ก **"ไม่ต้องแสดงอีก"** (สมาชิกใหม่ยังเห็นเสมอ)
  - ใต้รูป: ☐ ไม่ต้องแสดงอีก (ซ้าย ตัวขาว) · "ปิดหน้าต่างนี้" (ขวา ขีดเส้นใต้)
  - ปิดได้ 3 ทาง: แตะ X สีชมพูในรูป (มุมขวาบน — วางพื้นที่กด 40px ทับ ไม่วาด X ซ้ำ) · "ปิดหน้าต่างนี้" · แตะพื้นหลัง — ติ๊กไว้ตอนปิด → ไม่แสดงอีก
  - เมนู prototype: **"แสดง popup ต้อนรับอีกครั้ง"** ล้างค่าที่จำไว้
  - ตรวจแล้ว: ไม่ติ๊ก → ปิด → ไม่ขึ้นซ้ำในการเปิดแอปเดิม · ติ๊ก → ปิด → รีโหลด/เปิดใหม่ก็ไม่ขึ้น
- **การ์ดคะแนน | คอยน์ (หน้าแรก + โปรไฟล์)**: ">" ย้ายจากบรรทัด "คะแนนของคุณ / คอยน์ของคุณ" มาอยู่ขวา **กึ่งกลางแนวตั้งระหว่างตัวเลขกับบรรทัด "ซื้อสินค้าเพื่อสะสมคะแนน / ทำภารกิจเพื่อสะสมคอยน์"** · กด ">" → **คะแนน: หน้าสะสมคะแนน · คอยน์: หน้าภารกิจ** (เดิม → ประวัติ; ประวัติยังเข้าได้จากโปรไฟล์ › ประวัติคะแนนและคอยน์) · ข้อความยังเต็มบรรทัดบนจอ 375 · การ์ดที่ไม่มีบรรทัดวิธีได้ ">" ยังเป็นประวัติที่บรรทัดป้ายเหมือนเดิม
- **โปรไฟล์ › คูปองและประวัติ** เรียงใหม่: 1. คูปองของฉัน (เมื่อมีคูปอง) · 2. แลกคะแนนเป็นคูปอง · 3. ประวัติคะแนนและคอยน์ · 4. ประวัติการแลกของรางวัล
